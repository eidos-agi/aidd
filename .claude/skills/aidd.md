# /aidd

The method.

Read `README.md` and `doctrine/principles.md` first. Then:

1. Name the champion. It is `product`, publicly. For this forge: `eidos-agi/aidd`.
2. Name the frozen evaluator. It lives in the champion. If there is none, stop and extract contracts before generating code.
3. Name the generation repo. It is `product-vN`. Do not bash in the champion.
4. Name the five legs. If `ai-users/`, `frontend-testing-standards/`, `data-testing-standards/`, `validation-personas/`, or `simplicity-standards/` are missing, copy templates from this forge into the champion.
5. Name the plugins the surface needs. Mac → `plugins/mac-desktop/`. iPhone → `plugins/iphone/`. iPad → `plugins/ipad/`. Next.js + shadcn → `plugins/nextjs-shadcn/`. Do not collapse them. See `/aidd-plugin`.
6. Do not start a rebuild because the code is ugly. Check `doctrine/rebuild-triggers.md`. A trigger opens `product-vN`.
7. Read `doctrine/field.md` once. Error analysis first. Held-out is locked. Teeth or the suite is theater.

Do not edit held-out evals, `validation-personas/`, `simplicity-standards/`, or plugin gates in the same run that authors a candidate.
